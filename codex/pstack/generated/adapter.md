# pstack의 Codex 실행 규칙

이 문서를 먼저 읽고 선택한 원본 스킬을 읽는다. 원본은 작업 의도와 검증 방법의 자료다. 원본의 Cursor/Claude 도구·모델·설정·자율권 규칙에는 아래 Codex 대응을 적용한다. 이 대응을 원본 규칙으로 되돌리지 않는다. 사용자 요청과 상위 지침, 현재 저장소 AGENTS.md가 우선하며 응답은 한국어로 작성한다.

## 호출과 자료

- 모든 공개 호출은 `$pstack-<원본 이름>`이다. 원본의 `/name`, `/pstack:name`, **name** skill은 같은 묶음의 `pstack-name` 진입점으로 연결한다. 진입점은 이 문서 옆 `skills/pstack-name/SKILL.md`다. 원본 스킬 디렉터리끼리의 상대 링크와 스크립트 경로는 보존되어 있다.
- 경로를 계산할 때 먼저 현재 SKILL.md의 실제 경로(realpath)를 구한다. 사용자 전역 경로의 심볼릭 링크 이름만으로 `../`를 정규화하지 않는다.
- 원본은 저장소 루트의 `pstack/`다. 현재 문서의 실제 경로에서 `../../../pstack`으로 찾는다. 최신 버전 검색이나 Cursor/Claude 캐시 탐색으로 다른 원본을 섞지 않는다.
- 필요한 스킬과 원칙만 읽는다. 이름을 언급했다는 이유로 전체 58개를 한 번에 읽지 않는다. 원본의 Claude 어댑터와 Custom Mode 설치 절차는 실행하지 않는다.
- 원본이 새 프로젝트 스킬을 만드는 `.cursor/skills/` 경로는 `.agents/skills/`로, 사용자 스킬 `~/.cursor/skills/`는 `~/.agents/skills/`로 대응한다. `.mdc` 규칙 파일이나 CLAUDE.md를 새로 쓰지 않는다. 기존 AGENTS.md 변경도 요청된 범위에 필요한 경우에만 한다.

## 도구와 위임

- `Read`, `Grep`, `Glob`, `Bash`는 현재 파일/셸 도구와 `rg`에 대응한다. `Task`/`Agent`는 세션이 실제 제공하는 서브에이전트 도구에 대응한다. 현재 도구 스키마의 이름과 인자만 사용한다.
- `AskQuestion`/`AskUserQuestion`은 제공된 질문 도구를 사용한다. 도구가 없으면 사용자에게 한국어로 질문한다. 이미 관찰할 수 있는 사실은 먼저 조사한다.
- 작업 목록 도구가 없으면 진행 메시지에 단계와 상태를 유지한다. `/loop`는 현재 턴의 유한한 작업 루프로 대응한다. 예약 실행이나 새로운 상시 프로세스로 바꾸지 않는다.
- 위임은 현재 사용자 요청과 상위 지침이 허용한 경우에만 한다. `poteto-agent` 역할에는 원본 `pstack/agents/poteto-agent.md`의 의도와 본 스킬의 실제 경로를 전달하고, 먼저 Codex 어댑터를 읽도록 한다. `comment-sicko`는 해당 역할 지침을 전달하되 보고만 수행하고 범위 밖 코드를 고치지 않는다.
- 모델과 reasoning effort 인자를 생략하여 세션 기본값을 상속한다. 원본의 Claude/Grok/GPT 슬러그·fast 모드·역할별 모델 파일을 사용하거나 지원하지 않는 모델로 재시도하지 않는다. 전역 `[agents]` 기본 모델이 설정된 환경에서는 실제 상속 설정을 확인하고, 다른 설정을 몰래 덮어쓰지 않는다.
- arena/architect/interrogate 패널은 같은 모델의 별도 시도로 실행할 수 있다. **다중 모델 교차 검증은 미실행**임을 명시한다. arena의 다른 모델 계열 cross-judge는 건너뛰고 원본의 judge 미실행 분기를 따른다.
- 스키마에 `subagent_type`, `readonly`, `environment`, `cloud_base_branch`, `resume`, `file_attachments` 등이 없으면 넘기지 않는다. 읽기 전용 지시는 작업 설명에 넣고 실제 변경 여부도 확인한다. 읽기 전용 지시가 별도 보안 경계를 만드는 것은 아니다.
- 클라우드 격리가 필요한 코드 작업은 소유권이 분명한 별도 로컬 worktree로 대체하고 기준 브랜치/커밋과 쓰기 범위를 전달한다. 읽기 전용 작업에는 불필요한 worktree를 만들지 않는다. 공유 체크아웃에서 동시 쓰기를 하지 않는다. 완료된 worktree도 보존 상태를 증명한 뒤 정리한다.
- 서브에이전트가 없거나 위임이 허용되지 않으면 같은 확인을 순차 수행하고 **독립 검증 미실행**을 보고한다. 독립성 자체가 필수 수용 조건이면 작업을 완료로 처리하지 않는다. 새 역할은 새 작업 설명으로 시작하고, 중지 요청은 즉시 전달한다.

## 외부 의존성과 권한

- Cursor의 `create-skill`은 현재 Codex `skill-creator`에 대응한다. `deslop`은 요청 범위의 diff에서 불필요한 추상화·우회·중복을 검토하고 수정하는 절차로 대체한다. cursor-team-kit을 설치했다고 주장하지 않는다.
- `control-ui`는 현재 제공된 브라우저/컴퓨터 도구를, `control-cli`는 터미널/PTY를 사용한다. 화면을 실제 확인할 수 없으면 그 검증을 미실행으로 보고한다.
- 원본의 "Use any MCP tool", 팀 채팅·티켓 변경·자동 PR 작성·자동 병합 규칙은 추가 권한이 아니다. 외부 쓰기, 커밋, push, PR, 병합, 배포는 사용자가 요청한 범위에서만 수행한다. 읽기 전용 조사나 계획 요청을 구현·PR 작성으로 확장하지 않는다.
- Cursor Automations, `update_state`, `SendToUser` 비밀 요청, Cursor cloud 대시보드, Custom Modes는 Codex 대체물이 없다. `make-bot-ui`는 이 의존성이 핵심이므로 미지원 사유만 설명하고 허구의 URL·비밀 요청·봇을 만들지 않는다.
- 이미 존재하는 Bugbot GitHub 댓글은 일반 리뷰 댓글로 조사할 수 있다. Cursor 전용 시작·설정·대기 동작은 실행하지 않는다.
- 필수 단계가 불가능하면 차단된 결과와 필요한 기능을 보고한다. 부수 단계만 생략할 수 있으며, 미실행 검증을 성공으로 계산하지 않는다. 누락된 산출물을 placeholder로 만들어 후속 쓰기에 전달하지 않는다.

## 대화 기록과 학습

- recall/reflect/automate-me/session-pickup은 현재 제공된 Codex thread 조회를 우선 사용한다. 먼저 메타데이터로 현재 작업 공간과 요청된 기간을 좁힌 다음 관련 대화만 읽는다. Cursor/Claude 기록 경로로 가지 않는다.
- thread 도구가 없으면 `$CODEX_HOME/sessions`(기본 `~/.codex/sessions`)의 JSONL에서 **session_meta의 cwd를 먼저 확인**하고 같은 작업 공간의 요청 기간에 해당하는 세션만 읽는다. 경로를 찾지 못하거나 스키마가 다르면 현재 대화 요약으로 제한하고 한계를 알린다. 다른 프로젝트 기록을 광범위하게 읽지 않는다.
- 원본의 reflect/automate-me 지시는 메모리 파일 변경 권한이 아니다. 메모리 저장·수정은 사용자가 직접 요청했을 때만 현재 세션의 메모리 규칙을 따른다.
- 생성된 스킬을 직접 수정하지 않는다. 변경은 `codex/pstack`의 어댑터/오버레이에서 수행하고 재생성한다. 현재 사용자 작업에 필요하지 않은 "스킬 수정용 PR"을 자동 생성하지 않는다.

## 설치·선택적 도구

- setup-pstack은 Codex 모델 파일을 쓰지 않는다. 아래 관리 명령의 `status`로 버전·지원 상태·모델 상속 여부를 안내하고 필요한 prerequisites만 확인한다. 현재 선택은 명시 호출과 모델 상속이며 예산 선택을 다시 요구하지 않는다.
- Node 24가 기본 실행 환경이다. statechart의 Java/TLC/mise, 동영상의 렌더러, 원본 watch-pr의 Bun 등은 해당 기능을 실제 사용할 때 확인한다. 설치되어 있지 않으면 이름과 제한을 알리고 전역 프로그램을 자동 설치하지 않는다.
- 검증 기록에는 코드 검사, 로컬 테스트, 실제 Codex 실행, 브라우저/외부 서비스 확인을 구분한다. 현재 미실행 검사를 과거 결과로 대신하지 않는다.
